# Datasets and Data Provenance

## Available files

- `datasets/synthetic/workload_demand_hourly.csv` is generated by `scripts/run_milestone_experiments.py`. It contains 672 synthetic hourly request-count values created with seed 42, a daily and weekly cycle, an upward trend, and Gaussian noise. Timestamps are generated sample times beginning 2025-01-01 UTC; they are not observed production dates. The CSV records a `synthetic` provenance field and the seed on each row.
- `src/yieldops/workload/generator.py` contains four short synthetic prompt templates. The workload runner also creates indexed synthetic prompts at runtime; it does not save prompt data.
- Unit/integration tests create small synthetic telemetry records. The anomaly experiment creates synthetic latency points and injected anomaly labels in memory; these are not a real operational dataset.

There is no external or collected user dataset, no training corpus, no production traffic, no provider billing data, and no real model output dataset. Prompt and completion contents are excluded from retained telemetry.

## Forecast experiment use

The forecasting script uses the first 504 hours for training history and the final 168 hours as a time-ordered holdout. The last-value and 24-hour seasonal-naive methods see only the training history when producing the full horizon. Config and scores are stored under `experiments/configs/` and `experiments/results/`.

The anomaly evaluation uses seed 43 (base seed + 1), 240 synthetic latency points, and three injected high-latency labels. These data are generated inside the experiment script and are not represented as measured system behavior.

## Future data requirements

Before adding measured data, record source and license, collection timestamp, consent/retention policy, schema, row count, transformations, split rules, and provenance. Avoid prompt/response storage unless an explicit privacy design supports it. Forecasting must use time-aware splits; random splits would leak future patterns into training.
