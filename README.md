# YieldOps

YieldOps is an early-stage prototype for observing and optimizing self-hosted AI inference. Its long-term goal is to connect request telemetry, infrastructure cost, workload forecasting, controlled experiments, and human-approved recommendations.

## Current implementation

This repository currently contains a tested FastAPI prototype with a deterministic simulated inference backend. It validates inference-shaped requests, emits clearly labeled synthetic timing/token metadata, stores prompt-free telemetry in process memory, and summarizes latency percentiles. A synthetic HTTP runner exercises the request path.

**No LLM is served yet.** There is no GPU telemetry, persistent database, cost calculator, forecasting model, optimizer, or agent workflow. The smoke run validates API plumbing only; it is not evidence of model performance or optimization gains.

## What works today

- `GET /health` for a basic process response.
- `POST /v1/inference` for simulated output and request telemetry.
- `GET /v1/telemetry/summary` for in-memory request/token totals and simulated P50/P95/P99 latency.
- A concurrency-limited synthetic workload runner that reports client HTTP timing separately from simulated server timing.
- 10 passing unit and API behavior tests.

The recorded smoke run sent 20 synthetic requests at concurrency 4: 20 succeeded and 0 failed. Server inference latency was generated by fixed formulas. Client HTTP latency was measured on that run and includes local request/application overhead. Neither result is a GPU benchmark.

## Run locally

The project targets Python 3.12 and uses `uv.lock` for dependency resolution.

```bash
uv sync --python 3.12 --group dev
PYTHONPATH=src uv run --frozen uvicorn yieldops.api.main:app --reload
```

In another terminal, run a synthetic smoke workload:

```bash
PYTHONPATH=src uv run --frozen python scripts/run_synthetic_workload.py --base-url http://127.0.0.1:8000 --requests 20 --concurrency 4
```

Run the tests with:

```bash
uv run --frozen pytest
```

All inference timing is simulated until a compatible real model-serving backend and benchmark host are added. The API is a development prototype and is not intended for production traffic.
